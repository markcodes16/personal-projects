ROAD TO ETERNUS / WINDOWS DESKTOP / VERSION 0.1

Your home-PC training companion.

A local Windows application for recording sessions, collecting public match statistics, and reviewing your play. Focus pool: Mina, Warden, Abrams, and Pocket.

This is a runnable Python desktop release with a launcher, not a prebuilt or code-signed Windows .exe. Core logic was tested here. Windows capture, OBS connectivity, and your live match data still need the short home test below. Nothing needs to be installed on your work computer.

1. Open it at home

  1. Download the ZIP, right-click it, choose Extract All, and place the extracted folder somewhere you will keep it. Do not run it inside the ZIP.
  2. Install Python 3.11 or newer for Windows if needed, including the launcher and Tcl/Tk support. A normal python.org desktop installation includes these options. Python and OBS are separate prerequisites.
  3. Install OBS Studio if needed. OBS handles video capture and encoding.
  4. Double-click Start-Companion.cmd. On first run, it creates a private Python environment inside the app folder and downloads its two pinned connection libraries from PyPI. Internet access is required for that first setup. It does not require installing the companion as administrator.
  5. For convenient launching, create a Windows shortcut to Start-Companion.cmd on your desktop. Open the app before playing. It does not add itself to Windows startup.

2. Configure OBS once

  1. Finish OBS's recording setup. In Settings → Output, choose a recording folder and use MKV. You can remux a finished MKV to MP4 through OBS later. Choose an encoder and quality your machine can sustain; verify with a short test rather than assuming a setting guarantees no performance loss.
  2. In OBS, open Tools → WebSocket Server Settings. Enable the server, keep authentication enabled, and copy the port and password. In the companion's Setup tab, enter those values. Connection is restricted to 127.0.0.1; you do not need port forwarding. The password is held only in memory and must be re-entered after reopening the companion.
  3. Create an OBS scene named exactly Eternus - Deadlock. Add Game Capture, select Capture specific window, and choose the Deadlock window, usually citadel.exe. Keep only that Game Capture source enabled in this scene. The companion rejects other visible source types when starting.
  4. With Deadlock running, select that scene and verify the OBS preview shows the game. Review OBS's audio mixer. Global desktop or microphone audio still follows your OBS profile; mute what you do not want recorded.
  5. In the companion, choose Connect OBS, then Check scene. A scene check validates settings, not actual visible pixels or audio quality.
  6. Use Start recording now, play for about a minute, then Disarm / stop app recording. Open the saved file and verify video, sound, and frame pacing.

3. Record automatically

Select Arm auto recording. While the companion and OBS remain open, it checks for Deadlock every three seconds. It starts a recording when the game process is present and stops after about nine seconds of confirmed process absence. Arming while the game is already open also starts recording.

This is session detection, not guaranteed match-boundary detection. Menus, queue time, practice, and multiple matches can appear in one file. Disarm stops the recording started by this app. If another recording is already active in OBS, the app refuses to take it over. If you close the companion normally, it attempts to stop its recording first; after a crash or power interruption, check OBS manually.

The app refuses to start below 10 GB free and attempts to stop below 5 GB. These checks are not a storage quota and do not guarantee that a disk can never fill. It never deletes recordings automatically. Pausing or changing scenes in OBS can interrupt recording or alignment; stop and test again if that happens.

4. Add your account and sync

In Setup, enter a numeric Steam account ID, SteamID64, [U:1:account], or a steamcommunity.com/profiles/... URL. Vanity profile names are not resolved automatically. Save setup, then choose Sync matches now.

The app downloads available match history from Deadlock API, keeps raw fields, and attempts detailed metadata for up to three recent missing matches per sync. Auto-sync runs every ten minutes while the app is open, if enabled. Provider errors preserve your existing records. Detailed requests use cached/available metadata without forcing fresh Steam retrieval.

5. Review kills and deaths in a recording

  1. Select a match in Matches and choose Load selected match details, then open Event review.
  2. If the payload has recognized death timestamps or sampled kill/death counters, the app builds event rows. Metadata compatibility is provisional until checked against your real games. Unsupported layouts show an unavailable message, not invented timestamps.
  3. Choose Link video & align clocks. Select the video containing that match. At one clear frame, enter its video playback time and the game clock shown at that same frame. This establishes the offset. It also works if the recording began partway through the match.
  4. Choose an event and Open event in video. If VLC is installed or configured, it opens approximately 20 seconds before the event or interval. Otherwise the app opens your default player and tells you where to seek.
  5. Verify one death and one kill. Correct the alignment if needed. A sampled counter increase means the event happened within an interval; it does not reveal the exact frame. Compare recognized counts with summary counts to spot missing coverage.

You can export event CSVs. The Recording tab also offers manual kill/death buttons and exports those video-time marks separately. These are not global hotkeys. This release does not include reliable live kill-feed recognition, automatic highlight cutting, or automatic video-to-match alignment.

6. Keep the training project together

The Training tab contains the 24 lessons, statuses, and evidence notes. The full guide includes all four hero tracks. The web training app is available through the top button. Desktop and web progress are separate in this release; automatic cross-app synchronization is not implemented.

Local settings, cached match data, notes, recording references, and lesson progress live in %LOCALAPPDATA%\EternusCompanion. Actual videos stay in your OBS recording folder. “Back up local records” creates a SQLite backup; back up videos separately. To uninstall the companion, remove its extracted folder; keep the local-data folder if you want to retain progress. No service or scheduled task is installed.

Home verification checklist

  1. App launches and saves a lesson note across closing/reopening.
  2. OBS scene preview and one-minute test recording look and sound correct.
  3. Arming starts recording when Deadlock runs; disarming stops only this app's recording.
  4. At least three synced matches match your in-game history and account.
  5. Hero names and results look right; check provider coverage before trusting aggregates.
  6. For a metadata-supported game, compare timeline coverage to K/D totals and verify timestamps against the video.

If something fails, keep the error text and the relevant match ID. For event compatibility problems, use “Inspect all received stats” to inspect the actual payload. Do not send OBS passwords. A startup error is recorded in the local-data folder as last-error.txt.

Validation and sources

Seventeen automated core tests cover account normalization, clock offsets, conservative event extraction, local database updates and account separation, backup, recording ownership, low-space handling, and scene changes. Syntax was checked. Tests use synthetic metadata and a simulated OBS client. No actual Windows capture, GUI interaction, or end-to-end API call was validated in this environment; outbound API access here was restricted.

Technical references: Deadlock API specification; OBS remote control; OBS Game Capture; OBS WebSocket protocol; obsws-python SDK. Research checked September 10, 2026. Services and game schemas can change.
